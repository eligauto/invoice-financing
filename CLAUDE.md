# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project purpose

This will become an **invoice financing** platform: an intermediary that lets SMEs get
early payment on invoices owed to them by large companies (factoring-style), sitting
between big companies (the debtors/payers) and SMEs (the suppliers/sellers seeking
early liquidity). None of this domain logic exists yet.

## Project state

This is a virgin NestJS scaffold — `src/` only contains the stock starter files
(`AppModule` / `AppController` / `AppService`, `getHello()`, etc.) generated by
`nest new`. These are placeholder mockups, not real application code, and should be
replaced rather than extended as the actual domain model takes shape. There is no
database, no config module, and no domain code wired up yet. Expect to be building
the architecture from scratch rather than following existing patterns.

## Package manager

Use **pnpm**, not npm or yarn (`pnpm-lock.yaml` / `pnpm-workspace.yaml` are present).

## Commands

```bash
pnpm install

pnpm run start          # start
pnpm run start:dev      # watch mode
pnpm run start:debug    # watch mode with --debug

pnpm run build          # nest build

pnpm run lint           # oxlint --type-aware src/ test/
pnpm run format         # prettier --write "src/**/*.ts" "test/**/*.ts"

pnpm run test           # unit tests (*.spec.ts, via Jest)
pnpm run test:watch
pnpm run test:cov
pnpm run test:e2e       # e2e tests (test/**/*.e2e-spec.ts), separate Jest config at test/jest-e2e.json

# Run a single unit test file:
node --experimental-vm-modules ./node_modules/jest/bin/jest.js src/app.controller.spec.ts

# Run a single test by name:
node --experimental-vm-modules ./node_modules/jest/bin/jest.js -t "test name"
```

Jest is always invoked with `--experimental-vm-modules` (see the `test*` scripts in
`package.json`) — the project runs Jest under Node's native ESM support, not CommonJS.

## Architecture notes

- **Module system**: `tsconfig.json` sets `module`/`moduleResolution` to `nodenext` — this is a
  native ESM TypeScript project, not the CommonJS default NestJS ships with. Keep this in mind
  for import paths and any interop with CJS-only packages.
- **Path aliases**: `jest.config.ts` intentionally does not hardcode `moduleNameMapper` — it reads
  `compilerOptions.paths` out of `tsconfig.json` at config-load time via `pathsToModuleNameMapper`.
  If you add a path alias (e.g. via `nest g library`), add it only to `tsconfig.json`; Jest will
  pick it up automatically.
- **Linting**: uses `oxlint` (not ESLint) with `--type-aware`, configured in `.oxlintrc.json`.
  `typescript/no-floating-promises` is set to `error` — always `await` or explicitly `void` promises
  (see the `void bootstrap();` pattern in `src/main.ts`).
- **Formatting**: Prettier with `singleQuote: true` and `trailingComma: "all"` (`.prettierrc`).
